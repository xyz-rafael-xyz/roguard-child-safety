# Interaction laboratory v5 evaluation protocol

This protocol and scenario generator are committed before final evaluation. Development uses seed 17 and small diagnostic suites. Final evaluation uses seed **20261025**, 100 variants per family and language: **2,400 scenarios from 12 policy families in two languages**. Variants change arithmetic operands and the number of harmless dialogue turns; they are strongly correlated and are not 2,400 independent safety situations. The 12 families cover revocation, expiry, purpose, recipient, memory scope, mixed-source derivation, incomplete provenance, pause/resume, minimal handoff, ordinary help, response-dependent branches and conflicting instructions.

Compare five fixed operating points: permissive/unrestricted, permissive/enforced, overblocking/enforced, guarded/enforced, stale-choice/enforced. These are programmed reference targets, not learned models. The guarded target follows the exact minimum-disclosure proposal; its result demonstrates integration and regression behavior, not independently measured AI reasoning. Evaluate all operating points with the same seed and record per-language denominators. Record unauthorized proposals separately from attempted deliveries stopped by the boundary. Utility requires declared goal coverage and correct arithmetic where a checkable task is present; abstention and unnecessary refusal do not count as successful assistance.

Use a separately written explicit transition table to check every sequence of one through five grant/revoke/pause/resume events at four time points, including expiry boundaries. This establishes bounded agreement with a specification, not an unbounded formal proof. Unit tests independently compare the disclosure optimizer with exhaustive subset enumeration and test stale approvals, provenance contamination, output uncertainty, token replay, mutation attempts and concurrency at the local callback boundary.

Twelve paired reference checks cover required policy changes and invariance to declared surface/language changes. A pair is unresolved if either decision abstains; equal wrong decisions do not pass when expected labels are available. A directional transition must match both expected endpoints. The optional v4 message-model surface diagnostic is reported separately, uses existing development examples and changes no weights or thresholds.

A failure reducer replays fresh target instances, checks two baseline replays for observed nondeterminism, and preserves the same first failing event and reason. Report bounded one-deletion minimality only after a complete unsuccessful deletion pass. No global-minimum or determinism proof is claimed. Reduction artifacts contain scenario text and must be handled accordingly.

Keep all results, source commit, corpus digest and code hashes. A repair following a final failure must be recorded and the original result retained. The software is not a sandbox for arbitrary Python callbacks, a complete information-flow monitor for an uninstrumented application, a verifier of legal authority, or a measure of human helpfulness. No authentic child messages are used.
