# RoGuard Local v1.5.0 release scope

This release adds an exact finite-completion audit for corrected v1 D1/R1/S1 declared contracts. The new `roguard-v1-envelope` CLI and a third action in the Romanian/Ukrainian guided Studio hold supplied facts fixed and enumerate permissible completions of unknown fields. They show every decision code reachable under those completions and distinguish stable, sensitive, and unbounded cases. The JSON output has a [schema](../schema/v1-envelope-report.schema.json), excludes custom input values, and never triggers an external action.

D1 covers all Boolean completions and the three declared source roles. S1 covers valid applicability and pass states over its ten fixed criteria, at most 59,049 completions. R1 covers an unresolved recipient-concern flag only when its other policy facts are present. Missing routing strings or policy structures have no finite declared domain, so the tool reports `unbounded` instead of a certificate. Stability concerns the **decision code under declared symbolic completions**, not confidence in the facts, reason-code invariance, or safety of a real route.

The existing one-fact explorer remains useful for testing deliberate changes to known facts. The new audit answers a separate question: whether filling in current unknown fields can alter the declared-contract decision. Both use the same corrected v1 checker. Neither reads a child's message or estimates model accuracy. Trained adapters remain in the private research archive and out of this wheel; recent sealed synthetic studies still fail transfer targets. The reviewed taxonomy has owner-attested specialist approval at exact digests, while authentic-language model accuracy remains unestablished.
