# RoGuard Local v2.0.0 release scope

V2 adds an exact, field-level uncertainty audit for the corrected D1/R1/S1 declared-contract rules. A support criterion can now be `not_applicable`, `failed`, `passed`, or `unknown` independently of the other nine criteria. The CLI and local Studio enumerate every valid completion, report all reachable decision codes, provide one symbolic witness for each code, and rank unresolved facts by the worst number of decision codes remaining after one answer. This is an aid for deciding **which declared fact to clarify next**. It is not a confidence score, risk estimate, or probability distribution. The ranking is a one-step minimax heuristic, not a proof that asking that question alone resolves the decision.

The audit keeps the reviewed v1 taxonomy and policy rules; it changes the representation of missing support facts and the audit output. D1's unknown source role and Boolean facts, and R1's unresolved recipient concern, use the same corrected rules. Missing R1 names, roles, or scope structures still have no finite declared domain, so the report says `unbounded` and gives no witness or question ranking for that category. A `stable` result certifies only one decision **code** across the enumerated symbolic completions. It does not certify reason codes or the truth of the declarations. Witnesses contain only fixed field paths and symbolic state codes; custom routing identifiers and input text are not copied into the report.

Run the packaged `roguard-v2-audit` command on [Romanian](../examples/v2_uncertainty_ro.json) or [Ukrainian](../examples/v2_uncertainty_uk.json) examples. The [input](../schema/v2-audit-input.schema.json) and [report](../schema/v2-audit-report.schema.json) schemas define the contract. The [Studio guide](DECISION_STUDIO.md) explains the guided controls. The earlier v1 checker, explorer, and v1.5 envelope remain available for existing inputs.

The test suite compares partial support-state completions and returned witnesses against the corrected v1 rule engine, checks that resolving an unknown cannot introduce a new possible code, and exercises both language tags and the loopback API. These tests establish consistency of this **symbolic software contract**, not recognition accuracy for authentic Romanian or Ukrainian child language. V2 includes no trained text model or weights. The private research models' failed cross-surface results and the open external validation gates remain as recorded in [BENCHMARK.md](../BENCHMARK.md) and [Release gates](RELEASE_GATES.md). A separate human-reviewed, independent, prospective language study would be needed before claiming child-message detection accuracy.

The v2 design follows the general practice of [metamorphic testing for classifiers](https://www.cs.columbia.edu/wp-content/uploads/sites/7/2016/08/jss2011.pdf) in using relations between related inputs as checks, while its exact finite symbolic completion method is specific to RoGuard's declared contract. The work does not claim that metamorphic testing or minimax questioning was invented here.
