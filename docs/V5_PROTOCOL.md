# Frozen Romanian token-margin study, v5

This protocol is fixed before scoring the new batch-0013 test. The test has 96 abstract cards in 48 adjacent one-condition pairs, eight pairs per category. Its generator enumerates declared facts only. It contains no child communication or realistic response. The cards are a new surface test within the same symbolic policy domain, so a result cannot estimate real-world child-safety performance.

## Fixed intervention

Keep the v4 step-500 RoMistral adapter selected on batch-0010 development data, the pinned 4-bit base, the v4 category prompt, taxonomy, and category applicability. No further adapter training is permitted during this study. For each applicable category, run one forward pass and read the next-token logits for lowercase `da` and `nu`. Verify at runtime that each answer is a single token immediately following the prompt under the model chat template. Convert the two logits to `exp(da)/(exp(da)+exp(nu))` with a stable two-choice softmax. This is a conditional choice score, not a calibrated probability that a child is at risk.

The development batch is batch-0010 (36 cards, 18 pairs). For D1, R1, P1, and G1 fit one threshold each. Fit A1 and S1 jointly because both apply to `response` cards; each retains a separate threshold. For each category, candidates are 0, 1, and all midpoints between its distinct development scores. Select each category group by maximizing exact complete pairs, then exact cards, then true positives, then minimizing false positives, then minimizing distance from 0.5, then choosing lower thresholds. Save every development score, fitted threshold, and a leave-one-pair-out diagnostic in a hash-bound development record. Freeze and commit that record before any batch-0013 model inference. Cross-validation is a diagnostic, not a test-set replacement.

## One opening of batch-0013

Run the frozen token-margin classifier once on batch-0013. Compare against the same selected adapter using its original hard `da`/`nu` generation, and the pinned prompt-only RoMistral with the unchanged v4 prompt and eight-token cap. Both comparators use the same test cards. Include always-review and never-review references. Report exact cards, exact one-condition pairs, positive-to-negative flip direction, false review on 48 negative cards, strict parse for generation, and per-category precision and recall with raw counts. Preserve per-row outputs and hashes of the test batch, validation record, model weights, prompt, threshold record, and comparator outputs. Do not tune on this test; it is consumed after the first inference.

Success for this intervention requires more exact pairs than **both** learned comparators and recall of at least four of eight positives for **every** category, with no more than two false reviews among the eight negatives for **each** category. This demanding criterion is descriptive, not a gateway to child-facing deployment. If it fails, record the failure and keep the model as an experimental hint only. The exact structured policy checker remains the authoritative decision path for complete declared contracts. Ukrainian taxonomy and model outputs still require independent fluent review.
