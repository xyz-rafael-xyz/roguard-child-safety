# Release gates against the project requirements

This is a status record, not a claim of completion. It separates the **working declared-contract tool** from the **unvalidated language classifier**. This repository began as a public source snapshot and has since received public toolkit fixes. Trained weights and the historical Git record remain in a private research archive; see [Public release](PUBLIC_RELEASE.md). Any public model-weight release or package registration is a separate step.

The no-real-or-realistic-disclosure rule is essential and remains in force. It also means the current synthetic cards cannot establish D1 sensitivity to authentic child disclosures. A successful symbolic test would establish only symbolic-card performance. Before a real-language accuracy claim, the project needs independent language and child-safety review plus an evaluation design that respects the data rule and explicitly states the population it can represent. Recomputing a failed result should pass the integrity check while preserving the failure; repeating a consumed test until a score passes would invalidate the evidence.

An owner-supplied [first specialist memo](REVIEW_FEEDBACK_V2.md) informed the public README and explicitly said its reviewers did not read the taxonomy. A [second memo](TAXONOMY_REVIEW_V1.md) reviewed the earlier taxonomies, rejected D1 in both languages, and requested corrections to R1, S1, and wording. Separate v1 candidate texts and declared-card checks now implement those corrections. The second memo asks for a new signoff on the corrected exact bytes, so both candidate taxonomy records and the model-accuracy gate remain open.

The independent-batch intake now rejects an obvious Romanian/Ukrainian script mismatch and gives the separate content reviewer a hash-bound, content-free audit of close wording overlap with earlier batches **and different pairs in the candidate**. A [retrospective check](SURFACE_OVERLAP_AUDIT.md) flagged every card in three consumed generator batches against another pair at the 0.8 warning threshold. These warnings cannot prove native phrasing, independent authorship, semantic novelty, or label validity. The V16/V22 fusion audit also confirmed that a simple score average did not fix the failed development gate. These remain reasons to seek genuinely new, independently adjudicated cards rather than reuse consumed test labels.

On 30 September 2026, a fresh Python 3.12 virtual environment installed the package with `python -m pip install -e .`, passed all 228 unit tests, and ran the Romanian and Ukrainian routing, six-category contract, and word-cap CLI examples plus the four-line mixed JSONL example. The English [quickstart](../README.md#quickstart-english) now includes its own commands. This verifies the documented local declared-contract path; it does not establish model or language validity.

The author kit now requires a verified, committed model-freeze record before making independent test tasks and binds its digest through assembly, separate content review, and final intake. The active [V5 record](../eval/prospective/ro-v16-registered-study-freeze-v5.json) verifies that every named code, plan, and weight file already had its registered bytes at the cited pre-author Git commit as well as at current committed `HEAD`. It also binds the [prediction-seal protocol](STUDY_PREDICTION_SEAL.md) and a Git-order verifier requiring blind predictions to be committed before the author-labeled batch. V4 closed the source-commit byte gap; V5 closes an avoidable labeled-batch publication order risk. The historical V3 record itself passed a retrospective byte audit. The `roguard-human-eval-registered` command checks the model identifier in blind predictions against the active record; the original evaluator stays pinned to its pre-author input-integrity record. These controls detect accidental weight, code, or identifier drift; they cannot prove human authorship chronology or that the claimed model produced the predictions.

The public `calibrate()` path now rejects development records with invalid probabilities, source-kind-incompatible labels, or a category lacking either class. `screen()` validates text and all thresholds before invoking a caller-supplied scorer. These close input-handling errors; they do not improve the frozen model results or establish recall on unseen cards.

The v0.2 public package adds a loopback-only Decision Studio and a bounded one-fact explorer for the existing declared-contract checker. They expose exact decisions and sensitivity to supplied policy facts through a browser or CLI, with no external action or model download. They improve access to the deterministic workflow and its review evidence; the independent Romanian/Ukrainian language reviews and held-out model-accuracy gates remain open.

The declared boundary checker now separates recurrence of a protected field from a newly introduced unlisted field after correction. The same proposal can carry both `BOUNDARY_RECURRENCE` and `UNAUTHORIZED_REUSE`. This corrected a deterministic reason-code error; it does not improve or validate the language classifier. The 64-state P1 matrix and bilingual CLI regression cover the distinction.

The blinded review audit rejects answer streams whose row order does not match each reviewer's assigned packet. The Romanian-only `roguard-predict-abstract` command reads only the shuffled opaque packet and writes packet-hash-bound decisions from a pinned local mmBERT adapter at its fixed cutoff. The evaluator joins those decisions to the approved source only after checking the packet; source-ordered predictions cannot stand in for an independent study. It now rechecks packet and attested-source bytes at the end of evaluation, as well as answer and prediction bytes, so a mid-run mutation fails. This does not supply the missing human reviews or establish text-model accuracy.

The annotation CLI now writes a private SHA-256 packet binding before collecting answers and refuses to resume against changed bytes. Independent-batch audits require both reviewers' bindings; demonstration audits can still read older unbound answer streams while reporting that the packet binding was not verified. The binding cannot prove who performed the annotation.

The public `roguard-human-eval` command also records both packet-binding hashes and rechecks them through the final report. Its input-integrity wrapper is bound by a separate pre-author addendum, leaving the original V16 scoring-code freeze intact. This secures the evidence chain for a future independent abstract study; it is not a new measured model result.

An offline author kit now prepares separate balanced RO/UK D1/S1 workbooks, assembles unapproved candidates outside Git, and requires a distinct content-review declaration bound to exact bytes before repository intake. The current independent taxonomy reviews remain pending, so no real author task has been issued or study batch received. The kit checks structure and chronology declarations, not actual independence or semantic validity.

The prospective abstract-card evaluation now has a fixed numeric target registered before any independent batch exists: at least 44 adjudicated **one-fact pairs aligned to the declared factor**, 100% parse coverage, at least 0.90 recall, specificity, precision, and exact valid-pair rate overall, plus author and factor floors. Each author must declare balanced D1 or S1 factor coverage. The evaluator distinguishes an inconclusive human contrast set from a model miss and reports author surfaces, factor surfaces, and descriptive uncertainty intervals. This target concerns invented abstract cards only; it cannot close the authentic child-language or independent-review gates.

The [pre-author comparator freeze](PROSPECTIVE_BASELINE_FREEZE.md) now binds V16's existing weights, scoring path, evaluation code, and numeric-target protocol to exact hashes, checked in CI. It is a fixed failed-model baseline for a future independent Romanian abstract study, not a new accuracy result or proof of human study chronology.

The [Ukrainian model-family diagnostic](UK_MODEL_FAMILY_DIAGNOSTIC.md) reran three other pinned prompt-only bases on the consumed draft probe after only the seven documented in-memory A1 grammar corrections. Phi, Gemma, and Mistral each got 0/24 complete pairs; two frequently failed strict output parsing. The results are preserved with raw output and a CI replay, but they do not close the independent-review or held-out accuracy gates.

The [single-rule binary prompt diagnostic](UK_BINARY_PROMPT_DIAGNOSTIC.md) fixed strict parsing on that same consumed probe for all four pinned bases, yet their complete-pair counts were 0/24 to 5/24. The per-category tradeoffs make another selection on these cards scientifically unconvincing. A new Ukrainian study still requires fluent review and independent authors before its results can carry a held-out claim.

A direct Python API audit found that a malformed R1 card using strings instead of recipient sets could falsely pass through substring membership. A whitespace-only gate reviewer could also pass as a named owner. The checker now rejects malformed routing scopes, treats blank authority fields as missing, and validates field types across all seven structured card types before deciding. The [regression and contract audit](CONTRACT_AUDIT.md) cover these false-pass cases; this is an input-integrity repair, not a language-model accuracy gain.
