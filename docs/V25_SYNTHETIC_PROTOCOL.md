# V25: sealed bilingual synthetic metadata study

This is a new **exploratory** study of abstract annotation metadata in Romanian and Ukrainian. It is a response to the request for a synthetic held-out test, not a substitute for independent language or child-safety review. Neither language's cards contain child utterances, realistic disclosures, response drafts, or case narratives. The Ukrainian taxonomy is still a draft. The V25 files deliberately remain outside `load_approved()` and the live `screen()` path.

## Question and scope

Can one pinned multilingual encoder learn the `D1` and `S1` *metadata decisions* across wording families it did not see while fitting? `R1`, `P1`, `G1`, and a caller-declared `A1` word cap already have exact structured checks; a text classifier must not grant their permissions or stand in for those checks. V25 tests only the two categories that require linguistic interpretation. A good score would describe this controlled metadata population. It would not measure detection in children's messages, Ukrainian fluency, response adequacy, or a real-world safety outcome.

The generator creates adjacent negative/positive one-fact pairs. For `D1`, the fixed oracle is `check_disclosure_evidence()`: a minor source, a safety or support anchor, and either an indirect or an explicit support-seeking pattern. The changed factor cycles through source role, anchor, indirect pattern, and explicit request. For `S1`, `check_support_contract()` decides whether one named applicable response field fails; the changed factor is applicability or pass status. A separate applicable field always passes, so an inapplicable target is a true negative rather than a missing contract. There are eight target fields. The same latent fact rule is used in both languages, while the Romanian and Ukrainian metadata sentences have separate wording banks. No source card is translated to make the other language's card.

Each language/category has 192 training pairs, 48 development pairs, and 48 prospective test pairs: 1,536, 384, and 384 rows overall. Training uses styles 0–3, development style 4, and test styles 5–6 from the separately written language banks. The fixed pair order is negative then positive; both variants share a neutral random marker and clause order. The marker is independent of the label. The script checks pair counts, unique text, and the absence of category-code tokens and direct speech. Different styles and zero exact duplicates do **not** prove semantic independence or natural language quality.

## Seal and model choice

Run `python -m training.generate_v25_synthetic prepare` once. It writes training and development rows, saves a random 192-bit test seed only under ignored `review_runs/`, and commits only its SHA-256, the generator and wording hashes, taxonomy hashes, split hashes, and the fact that zero test rows exist. Commit and push this protocol, code, data, and commitment before fitting. Do not inspect or generate actual test rows during model selection. Unit tests may exercise the generator with a separate, explicitly dummy seed.

Fit an experimental LoRA two-class head on the pinned `jhu-clsp/mmBERT-base` revision already used by RoGuard. Use one bilingual prompt per applicable D1 or S1 rule, pairwise cross entropy plus a positive-over-negative ranking term, balanced Romanian/Ukrainian and D1/S1 exposure, and a fixed 256-token cap. Register seed, optimizer, rate, epoch count, and selection rule in the trainer **before** fitting. Select one epoch and one decision cutoff on development only. Preserve every epoch, raw scores, and any failed gate. A simple character n-gram classifier trained on exactly the same training rows is a descriptive baseline; if it matches or beats the encoder, report that directly.

The selected model, prompt, cutoff, code hashes, and development report must be committed before `reveal` accepts the local test seed. The reveal command requires a clean Git worktree and a committed selection record bound to the seed commitment. Generate the test once, score the unchanged model and baseline once, and commit the exact test rows, predictions, report, and failure or success. Do not choose a new model or cutoff after reading test labels. A later repair needs a new prospective seed and a revised, separately committed wording bank or authoring source.

## Fixed report and success target

Count strict parse coverage, exact cards, complete one-fact pairs, positive recall, negative specificity, precision, false review load, per-language/category cells, D1 changed factors, S1 applicability versus pass factors, and the two test styles separately. Report binomial uncertainty intervals and the same metrics for always-review, never-review, and the character n-gram baseline. Do not pool a good Romanian result over a failed Ukrainian result.

The predeclared synthetic target is **at least 44/48 complete pairs in each of the four language/category cells**, at least 44/48 positive recoveries and 44/48 correctly unreviewed negatives in each cell, 100% parse coverage, at least 9/12 complete D1 pairs for every changed factor in each language, and at least 20/24 complete S1 pairs for each changed factor in each language. These are deliberately stricter than the aggregate score alone. A pass is a narrow same-origin synthetic transfer result. It does not open `verify_independent_reviews()`, authorize use on free-form messages, or replace the planned independent author and adjudication study.

The synthetic study cannot resolve the missing DiscloseBench manuscript, establish Romanian/Ukrainian idiomatic accuracy, or manufacture an independent reviewer. Those remain separate release gates even if every numeric synthetic target passes.
