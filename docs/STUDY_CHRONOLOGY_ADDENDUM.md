# Pre-author chronology for a prospective abstract-card study

This addendum resolves an ordering ambiguity in the frozen [human validation protocol](HUMAN_VALIDATION_PROTOCOL.md). The model, prompt, cutoff, prediction path, evaluation path, and numeric target must be committed and registered **before either author receives an assignment or creates any test card**. Freezing after the cards are written, even before their labels are opened, does not create an unseen test: the wording itself could already influence the model or prompt. The original protocol bytes remain intact as historical preregistration evidence; this addendum governs a new study started after this correction.

The [author kit](AUTHOR_KIT.md) enforces that order mechanically at `new`, then rechecks the freeze at `assemble` and `seal`. A registered study record names a `pre_author_git_commit` and exact SHA-256 digests for the files it depends on. The checker now verifies that each named file had its registered bytes **at that commit**, as well as at the current committed `HEAD`. This closes the case where a record cites an older ancestor while relying on code or weights committed later. The study owner must separately preserve the Git push, author assignment, authorship, review, and model-operator handoff chronology; software cannot prove when a person actually saw a card or worked independently.

Use one prospective test batch only once for model selection. First complete independent taxonomy review. Then register the model and plan, issue separate author assignments, collect new language-native abstract cards, obtain separate content review, seal and blind the batch, commit opaque model predictions, collect independent judgments, adjudicate while blind to predictions, and finally score. A failed result stays in the record. A later candidate requires a newly authored and reviewed test batch. No abstract-card result establishes detection accuracy on authentic child messages.
