# Research and release gates

**Historical roadmap:** Several status sentences below describe the earlier v0.2/v0.1 taxonomy and model experiments. The corrected v1 candidates have since received owner-attested, exact-digest reviews. The [v1 evidence ledger](V1_EVIDENCE.md) is the current release status; independent model-study evidence is still missing.

RoGuard's goal is a useful, inspectable Romanian and Ukrainian child-safety evaluation toolkit. Current evidence supports a **structured contract checker** in both languages and an experimental Romanian abstract-card classifier. It does not support a claim of high accuracy on authentic child language or a claim to be the first child-safety guardrail. [The measured model results](../BENCHMARK.md) are the reason to keep these claims separate.

## Execution questions

1. **What can be made exact?** Routing, permission, boundary, gate, and declared word-cap decisions can be checked against caller-supplied contracts. Build independent truth tables and counterfactual pairs for these checks; report both missed violations and false restrictions. Missing policy facts must remain `incomplete`.
2. **What requires linguistic judgment?** D1 and S1 need context and language expertise. The synthetic-only rule prevents using real disclosure transcripts or realistic paraphrases. Pattern-level cards can test annotation logic, but cannot measure detection on real child messages. Distinguish a research baseline from a deployable detector.
3. **Does a model beat a simple baseline?** Compare each candidate against a prompt-only base, the typed reference checks, and an always-review baseline. Freeze model, prompt, thresholds, and test generator before examining each new test. Report exact match, per-category precision/recall, strict parsing, false review load, and pair consistency.
4. **Do the languages work independently?** The Ukrainian taxonomy was written as a separate draft. It needs a fluent Ukrainian second reader and child-safety subject review before a language claim. English-to-Ukrainian translation of Romanian cards would be a weak benchmark. Use Ukrainian-authored abstract descriptions and a pinned multilingual or Ukrainian base model for a separately reported pilot.
5. **Can someone reproduce and use it?** A clean install, local JSON CLI, CI, attested batches, pinned model revisions, and frozen prediction files must work from Git. The CLI must not send data or take external action. Model weights require a separate license and publication decision.

The release can be useful before the linguistic classifier reaches a deployment threshold: the declared-contract checks already expose why a proposed action needs review. Their correctness still depends on the completeness and truth of facts supplied by the caller. An independent reviewer is required before any operational child-safety claim.

The [Romanian second-reader packet](RO_REVIEW_PACKET.md) and [Ukrainian review packet](UK_REVIEW_PACKET.md) specify the exact taxonomy hashes and questions for independent review. Neither packet is an approval record. The [review record gate](REVIEW_GATE.md) now checks two distinct disciplines and six accepted category decisions against the taxonomy digest. Both actual independent records remain pending. The Ukrainian training gate stays closed until review is returned and recorded; the Romanian classifier still needs authentic-language validity evidence before an accuracy claim.

A [pinned Ukrainian encoder candidate audit](UK_ENCODER_CANDIDATES.md) now compares only tokenizer fit on the consumed abstract probe and registers a later head-to-head study. It makes no Ukrainian model-accuracy claim and does not open the human-review gate.

A [source-backed role terminology audit](ROLE_TERMINOLOGY_AUDIT.md) identifies a concrete bilingual review question: Romanian *tutore* and Ukrainian *піклувальник* can carry specific legal meanings even though RoGuard uses fictional policy roles. The reviewers must choose and justify the product-facing terms; no role string can confer access in the checker.

The local declared-contract path now supports ordered JSONL batches, a one-fact `roguard-contrast` command, and a [documented permission state audit](CONTRACT_AUDIT.md). A model-agnostic `roguard-pairs` command measures pair consistency, per-category errors, strict parsing, and false review load against an attested abstract batch. These features make failure visible and repeatable; they do not turn the present classifier into a deployable detector.

The content-free D1/S1 review form and ID-matched batch agreement audit now provide a reproducible path to measure two reviewers' judgments on permitted abstract cards in either language. No such independent annotations have been collected, and agreement alone would not validate authenticity, label correctness, or child-safety outcomes.

The [prospective human validation protocol](HUMAN_VALIDATION_PROTOCOL.md) fixes the order: independent review of exact taxonomy bytes, a committed model and evaluation freeze before author assignments, new language-native abstract cards, a pushed blind-prediction commit before publishing their intended labels, then blinded double annotation and adjudication before the frozen model comparison. The chronology addendum and prediction-seal protocol make this order explicit. It makes the remaining human evidence requirement concrete without allowing realistic disclosure content into the repository.

A [retrospective surface-overlap audit](SURFACE_OVERLAP_AUDIT.md) found that every card in three consumed generator-authored batches had a near lexical match in another pair at the declared 0.8 warning threshold. The independent intake now exposes the same content-free cross-pair warning to its human content reviewer; it is a review aid, not a semantic-independence certificate.

The [reviewer handoff](REVIEWER_HANDOFF.md) provides the exact taxonomy digests, reviewer qualifications, official institutional introduction routes, and a draft invitation. No contact or review has happened yet.

All six taxonomy codes can now be represented in a caller-declared structured report. D1 and S1 consume explicit, previously reviewed pattern and response-field facts, not raw text. This closes an interface gap for human-led review while leaving the need for fluent language and child-safety validation unchanged.
