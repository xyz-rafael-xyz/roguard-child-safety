# Pre-author model freeze for independent abstract studies

The author kit requires a model-freeze JSON file under `eval/prospective/` before it creates either author's task. Use the [Romanian V16 registered-study V5 record](../eval/prospective/ro-v16-registered-study-freeze-v5.json) for a new D1 or S1 abstract study. It binds the existing V16 **research comparator** to the prediction and evaluation entrypoints, all 43 RoGuard Python source files present at its pre-author commit, the [chronology addendum](STUDY_CHRONOLOGY_ADDENDUM.md), and the [blind-prediction seal](STUDY_PREDICTION_SEAL.md) with its Git-order verifier. It does not claim the model met its prior accuracy gates. The [verifier](../eval/verify_registered_study_freeze.py) checks those frozen bytes at the named pre-author commit and at the current committed `HEAD`; later unrelated source files do not retroactively enter the freeze. The [older V16 baseline record](../eval/prospective/ro-v16-baseline-freeze.json) and its [verifier](../eval/verify_prospective_baseline.py) remain unchanged as historical preregistration evidence; they predate the registered evaluator. `roguard-author-kit new --freeze-record eval/prospective/ro-v16-registered-study-freeze-v5.json` checks the active record before authors receive tasks.

The first [registered-study draft](../eval/prospective/ro-v16-registered-study-freeze.json) was superseded before any author task or independent batch: it exposed the older baseline as an accepted author-kit input. The V2 code closes that path. The first draft remains in Git to make the correction visible, but its named source hash no longer matches the current checker and it cannot start a study.

The [V2 record](../eval/prospective/ro-v16-registered-study-freeze-v2.json) was also superseded before any author task. Its intake audit checked candidate cards against prior batches but missed near copies across different pairs in the new candidate. V3 freezes the [cross-pair warning](SURFACE_OVERLAP_AUDIT.md) alongside the same V16 model and prediction path. V2 remains historical and its source digest no longer matches `HEAD`.

The [V3 record](../eval/prospective/ro-v16-registered-study-freeze-v3.json) was likewise superseded before any author task. Its checker required the named source commit to be an ancestor, but did not verify that the registered bytes existed at that commit. The historical V3 bytes themselves passed a retrospective source-commit audit. V4 strengthens the general checker and fixes the author-before-freeze ambiguity through the addendum. V3 remains in Git; its old `src/roguard/study_freeze.py` digest intentionally no longer matches `HEAD`.

The [V4 record](../eval/prospective/ro-v16-registered-study-freeze-v4.json) was superseded before any author task after finding that approved, author-labeled batch files might be pushed before blind predictions. V5 adds the prediction-seal order and a content-free commit-order verifier. The V16 model, cutoff, prediction path, and numeric target remain the same. V4 remains in Git as a valid record of its own registered bytes but is not the current study handoff.

For a later model, create and commit a new record **before giving either author a task**. It must name `schema_version: 1`, `status: registered_model_before_independent_batch`, an ISO `registered_on` date, a 40-character `pre_author_git_commit`, `language`, a nonempty `categories` array from `D1` and `S1`, `input_scope: independently_authored_abstract_cards_only`, the relative `adapter_dir`, nonempty `model_id`, numeric `cutoff` between 0 and 1, a short `prediction_model_id`, and a `sha256` map of committed relative file paths to 64-character lowercase digests. Name distinct `predictor_entrypoint` and `evaluator_entrypoint` Python files in that map. The map must also include the adapter's `research.json` and one `.safetensors` weight file. Include the prediction and evaluation code's imported local modules so later changes to their decisions cannot silently enter the study. The adapter manifest must agree on language, cutoff, and weight hash. A new Ukrainian predictor and model study would need their own record; the present Romanian predictor rejects Ukrainian packets.

At `new`, `assemble`, `seal`, and direct independent-batch intake, RoGuard rechecks the record and its named files against both the current commit and the named source commit. The record path and digest travel in each private author workbook, the owner assignment map, the assembly manifest, and the final provenance. The [registered evaluator](../src/roguard/human_eval_registered.py) then rejects a blind prediction file whose declared `model_id` differs from the recorded prediction identifier. The older `roguard-human-eval` command remains pinned to its pre-author input-integrity addendum; use `roguard-human-eval-registered` for a newly independently authored model study.

These checks establish file identity and catch accidental drift or identifier swaps. They do not prove when a person wrote a card, that authors worked independently, or that the named model actually generated a prediction. Preserve the Git push record, private author and reviewer declarations, and model-operator handoff as separate chronology evidence. An independent abstract result cannot establish accuracy on authentic child language under the project's data rule.
