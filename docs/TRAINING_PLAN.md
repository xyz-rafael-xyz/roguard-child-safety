# Romanian pilot training and evaluation

RoGuard's approved v0.2 taxonomy separates a linguistic signal (`D1`) and response defects (`A1`, `S1`) from policy and workflow checks (`R1`, `P1`, `G1`). The latter three have [pure reference functions](../src/roguard/policy.py) when a caller supplies complete, fictional structured cards. A learned card classifier cannot grant access or replace those checks.

## Data and provenance gates

- Batch 0004 has 28 human-approved training cards. Batches [0005](../data/synthetic/batch-0005.preview.md), [0006](../data/synthetic/batch-0006.preview.md), and [0007](../data/synthetic/batch-0007.preview.md) were human-approved separately on 29 September 2026. They have 60 training, 40 development, and 40 held-out test cards, respectively. The user later removed per-batch human review; future generated batches require reproducible automated validation.
- The approved batches are abstract descriptors with held-out wording and symbolic values. Some decision structures necessarily recur, so even a high test score would measure this narrow card format, not authentic Romanian messages or real child-safety outcomes.
- The [candidate audit](../data/synthetic/pilot-audit.json) found zero exact duplicate card texts and zero category-code tokens inside card text; its largest same-kind train/test character similarity was 0.872. This check does not prove semantic independence.
- `load_approved()` retains its historical name and accepts exact-byte human approvals or registered automated attestations. Batch 0008 binds its JSONL, preview, audit, generator, taxonomy, and every row ID. Training and evaluation use explicitly named batches; test rows are rejected by the trainer. The preview must contain each row and label verbatim.
- A 200-step local adapter run completed on the 88 approved training cards and 40 development cards. Its logged validation losses were 8.266 at step 1, 0.484 at step 50, 0.539 at step 100, 0.341 at step 150, and 0.260 at step 200. These losses do not measure the held-out test set.
- [Full development-set diagnosis](../eval/runs/ro-v1-dev.json) after the frozen pilot showed 18/40 exact matches, the same category-level pattern as the held-out run: `D1`, `A1`, `P1`, and `S1` had zero recall; `R1` and `G1` each had four true and four false positives. This supports a class-collapse diagnosis, but does not make the held-out set available for another round of model selection. A future iteration needs a new independently generated, attested test batch.
- A second 200-step adapter used **the same approved train and development cards** with a versioned prompt that states only the rules applicable to the card type. On the [development split](../eval/runs/ro-v2-dev.json), it parsed 40/40 and exactly matched 25/40 cards. `D1` and `S1` each recovered four positives without false positives there; `A1` still recovered none, `P1` recovered two of four, and `R1`/`G1` still had false positives. The type-only shortcut observed in batch 0007 motivated this prompt change, so batch 0007 is no longer an independent test for the second adapter. These are development findings, not a new held-out benchmark.
- A [prompt-only base-model run](../eval/runs/romistral-base-v2-dev.json) on the same 40 development cards parsed 38/40 and exactly matched 23/40. The second adapter gained two exact matches and removed two parse failures, but its `A1` recall was 0/4 versus 2/4 for the base; its `P1` recall was 2/4 versus 4/4 for the base, with fewer false positives. This is too small and uneven a development comparison to establish a useful fine-tuning gain. It strengthens the case for more independently generated variation and typed deterministic checks, rather than claiming that lower token loss produced reliable decisions.
- [Batch 0008](../data/synthetic/batch-0008.preview.md) is a new 40-card test with four positives per category. Its [surface audit](../data/synthetic/batch-0008.audit.json) found no exact duplicates against earlier batches and maximum same-kind character similarity 0.674. Structural rule overlap remains. The registered generator reproduced every row; [the automated attestation](../data/synthetic/batch-0008.review.json) binds exact inputs. The second adapter and the fixed base comparator were evaluated once on batch 0008; see [BENCHMARK](../BENCHMARK.md).

## Apple Silicon path

This Mac has 16 GB of unified memory. The current [RoMistral model card](https://huggingface.co/OpenLLM-Ro/RoMistral-7b-Instruct) identifies it as a Romanian 7B model under CC BY-NC 4.0. Its 14.5 GB full precision weights are a poor starting point for the existing PyTorch sequence classifier trainer on this machine. [MLX-LM](https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/LORA.md) supports Mistral QLoRA and local prompt/completion files. MLX-LM 0.31.3 installed locally, the pinned source weights were verified, and a 4-bit model was converted under ignored `checkpoints/`. It loaded and answered a generic Romanian prompt. The completed adapter run reported 5.240 GB peak MLX memory; this is not whole-system memory use.

`training/prepare_mlx.py` exports attested train and development cards only. `training/train_mlx.py` uses rank 16, scale 2 (the MLX equivalent of alpha 32 / rank 16), prompt masking, eight adapter layers, batch size one, and gradient checkpointing. These are pilot settings, not tuned results. The model outputs canonical category codes or `NONE`; malformed output is counted separately during evaluation. `MLXClassifier` exposes hard 0/1 values to the package API. They are **not calibrated probabilities**. The PyTorch classifier path remains an alternative for hardware that can run it.

The second adapter records `prompt_version=v2` in its metadata; inference selects the same prompt version used for fitting. On the 128 approved training and development cards, the complete v2 chat-template sequence measured 162–252 tokens, below the 512-token training limit. For a structured `A1` card with a caller supplied word cap, `check_readability_contract()` now checks the numeric limit deterministically. It does not establish an age-appropriate Romanian readability threshold or preserve the semantic support step.

To reproduce that development adapter from the local pinned base, run `training/train_mlx.py` with the three approved `--batch` arguments shown in the README, `--prompt-version v2`, and `--output checkpoints/ro-v2`. The resulting local adapter and its metadata remain under ignored `checkpoints/`. The recorded [development output](../eval/runs/ro-v2-dev.json), [base-model comparator](../eval/runs/romistral-base-v2-dev.json), and [run manifest](../eval/runs/ro-v2-dev-manifest.json) preserve the measured comparison. A new generated batch must pass `training/validate_generated.py` before ingestion; batch 0008 passed and has now been consumed as a test.

The pinned RoMistral tokenizer loaded locally before the weights finished downloading. Across all 168 current abstract cards, complete prompt plus completion lengths were 204–255 tokens, within the 512-token training limit. This checks truncation only; it says nothing about classification quality.

Install the `[mlx]` and `[train]` optional dependencies in separate environments. The checked MLX-LM version requires Transformers 5, while the experimental PyTorch sequence-classifier path currently pins Transformers 4. Model conversion uses the exact upstream revision recorded in the README and the RoMistral entry in `eval/models.json`; the revision and license should be rechecked before any later run.

`training/convert_base.py` compares each downloaded source weight with the SHA-256 values published for the pinned Hugging Face revision before running the local 4-bit converter. It records hashes of the converted weights and configuration. `training/train_mlx.py` checks that provenance again before fitting. This protects the run record from silently substituting a different Mistral checkpoint; it does not validate the model's safety.

The [held-out reports](../BENCHMARK.md) include per-category support, true positives, false positives, false negatives, precision, recall, and strict parse rate. Unparsed outputs count as missed positive labels and are shown separately. Development cards are for model selection; each test batch is opened once for its frozen comparison. Results are weak even on abstract cards. A later study needs independently authored source templates, substantially more diverse positive and negative cards for each category, subcode and evidence-band annotation, a Romanian second reader, and a domain expert before any claim about practical use. The next automatically validated test batch must stay closed during model or prompt changes.

## Paired-card diagnosis and binary study

The [frozen v3 comparison](../BENCHMARK.md#frozen-romanian-paired-card-comparison-batch-0011) tested the 600-step adapter and five pinned prompt-only bases on 24 one-factor pairs. The adapter made 25/48 exact card matches but only 2/24 exact pairs and had zero recall in five categories. On the development split it made 19/36 exact matches with the same five zero-recall categories. Its low false-review rate came from almost always outputting `NONE`. Most prompt-only bases tended to flag both sides of a pair. The final validation loss rising from 0.184 at step 400 to 0.279 at step 600 is another warning, although loss alone does not identify the classification failure.

The [preregistered v4 study](V4_PROTOCOL.md) asks a separate balanced `da`/`nu` question for each applicable category. It kept the 288 training and 36 development cards, expanded them to 480 training and 48 development category tasks, and repeated positive A1/S1 training tasks to make the training targets exactly 240/240. A tokenizer audit changed the targets from uppercase to lowercase before any test inference; both lowercase targets are one token in the pinned tokenizer. Batch 0012 was a separate, automatically attested 48-card test sealed before fitting; its maximum same-kind character similarity to earlier cards was 0.629. The frozen development rule chose step 500 before test inference. On batch 0012, that adapter matched 28/48 cards and 4/24 complete pairs, with zero recall on P1, G1, and S1. Prompt-only RoMistral made 6/24 complete pairs and Qwen3 made 5/24, both with substantially more false reviews. [Full category counts](../BENCHMARK.md#frozen-romanian-binary-paired-card-comparison-batch-0012) show that binary targets did not solve the decision-boundary problem.

Further fitting on the same templates is unlikely to establish real child-safety accuracy. The next research gate is an independently authored, still abstract Romanian and Ukrainian card set with more varied positive and negative forms, expert review of D1 and S1 boundaries, and language-specific readability validation. The current software remains a reproducible evaluation rig and a read-only checker for declared contracts. It must not advertise the learned adapter as a live child-language detector.

The [v5 protocol](V5_PROTOCOL.md) kept the v4 weights and prompt fixed, read the next-token `da`/`nu` margin, and selected thresholds on batch 0010 only. Its 11/18 exact development pairs dropped to **2/48** on the new batch-0013 test; five of six categories had zero positive recall. The hard-output adapter reached 8/48 pairs, and prompt-only RoMistral 9/48 with 31/48 false reviews on negatives. [Full counts](../BENCHMARK.md#frozen-romanian-token-margin-comparison-batch-0013) show that threshold fitting did not solve the surface-generalization problem. Batch 0013 is consumed. Further synthetic fitting must use a new sealed test, and no synthetic score can establish real child-language detection without independent expert evidence.

The later [v6 compositional](V6_PROTOCOL.md), [v7 Qwen transfer](V7_PROTOCOL.md), and [v8 balanced Qwen](V8_PROTOCOL.md) studies each used a new sealed symbolic-card test. V6 reached 9/72 complete pairs on batch 0016. V7's trained output format failed strict parsing on all 144 batch-0017 cards. V8 repaired parsing to 144/144 and balanced category exposure, yet reached only 13/72 pairs on batch 0018, below its parser-matched v7 comparator's 15/72. Both adapters missed all S1 positives on batch 0018. These failures narrow the next useful research step: independently authored abstract boundary cases and expert review, especially for D1 and S1, rather than another fit on the same templates. Batches 0016–0018 are consumed and cannot guide another selection.

The [v9a pairwise mmBERT study](V9A_AMENDMENT.md) changed model family after an interrupted full-weight fit and selected its threshold only on batch 0015. Its [fresh batch-0019 comparison](../BENCHMARK.md#frozen-romanian-pair-trained-encoder-comparison-batch-0019) reached 28/72 complete pairs against Qwen v8's 22/72, but still failed the accuracy target with 26/72 false reviews. A1 and S1 each falsely flagged 20 applicable cards. The [v10 protocol](V10_PROTOCOL.md) targets missing cross-category negative tasks on a separately sealed batch 0020. This is an abstract-card experiment, not a route to claim real-child detection from template variations alone. Batch 0019 is consumed.

The [v10 frozen result](../BENCHMARK.md#frozen-romanian-cross-category-encoder-comparison-batch-0020) improved development pairs to 45/48 with only 3/48 false reviews, but transferred to 28/72 pairs and 40/72 false reviews on new wording. This failure is a distribution-shift warning, especially for arbitrary numeric A1 comparisons and changed Boolean wording in G1. Batch 0020 is consumed. The next fit needs genuinely broader abstract training surfaces and a fresh test, while the usable tool should continue to compute declared numerical and workflow contracts exactly instead of treating an encoder score as authority.

The [v11 broader-surface study](V11_PROTOCOL.md) did that on 2,304 train cards, 144 development cards, and a separate 144-card test. Its [frozen comparison](../BENCHMARK.md#frozen-romanian-surface-generalization-comparison-batch-0023) reached 47/72 exact pairs and 8/72 false reviews, below the unchanged v10 adapter's 53/72 pairs on the same cards. V11's selected shared threshold missed every A1 positive. A [pretest metadata amendment](V11_PRETEST_AMENDMENT.md) records and repairs a copied development-file tag without changing model weights or selected scores. Batches 0020 and 0023 are consumed. Further iteration should route caller-declared numeric and workflow facts to exact checks and evaluate linguistic D1/S1 signals separately; more template surfaces alone did not make a dependable six-category text classifier.
